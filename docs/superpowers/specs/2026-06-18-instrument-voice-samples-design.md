# SP3 — Instrument-Voice Samples Design Spec

> **Status:** Design. Built on top of the SP1 sample pipeline (already on `main`) and the Riddim dub engine (currently on `feat/dub-music-generator`).
>
> **Hard prerequisite (separate ticket):** the Riddim engine must be merged into `main` first. See "Prerequisite: the Riddim merge" below. SP3 does not own that merge as part of its diff; it consumes it.

## Goal

Let a user replace a single Riddim-engine instrument **voice** (kick, snare, hat, shaker, perc, bass, organ, skank, melodica) with their own recorded/imported/community sample, so a beatboxed kick or hummed bass plays inside the generated dub loop.

The clean injection point already exists: `RiddimEngine` reads every voice purely through `library.buffer(for:)` and `library.rootMidiNote(for:)` (verified in `Backyamon/Audio/Riddim/RiddimEngine.swift`). A runtime per-voice override on `SampleLibrary` swaps a voice with **zero** changes to engine logic (`sampleForHit`, `repitch`, `renderLoopBuffer`, `renderProcessedLoop`, `renderToFile`, the FX chain are all untouched).

Two corrections drove this spec versus the original framing, both verified against the tree:

1. **The merge is routine, not the riskiest unit.** A real `git merge-tree --write-tree main feat/dub-music-generator` produces conflicts in exactly **4 generated/config files**: `.gitignore`, `Backyamon.xcodeproj/project.pbxproj`, `Backyamon.xcodeproj/xcshareddata/xcschemes/Backyamon.xcscheme`, and `project.yml`. The dub branch's merge-base is `15540c2` — the commit immediately **before** the SP1 merge — so SP1 files never existed on dub and are **not deleted**. `SoundManager.swift` auto-merges with zero conflicts and ends up with **both** `loadCustomMusic(url:)` (SP1) and `loadCustomMusic(fileURL:)` (dub). The pbxproj/xcscheme conflicts are regenerated by `xcodegen generate` and must not be hand-edited; only `project.yml` needs a human union decision.

2. **SP3 must own a render-and-play trigger or it produces no audio.** No view on either branch instantiates `RiddimEngine` (it has a throwing `init()` that loads 9 bundled WAVs, and `private let library: SampleLibrary` with no accessor). Without an engine owner and a "Generate & Play" trigger, an equipped override has nothing to attach to and is never audible. SP3 therefore brings a minimal owner + Generate/Play surface **into scope** so the slice is demonstrably end-to-end audible.

## Context — how it fits

- **SP1 (on `main`, reused verbatim):** `AudioRecorder` (AAC mono 44.1k capture: `recorderSettings`, `makeTempURL`, `requestRecordPermission`, `audioDurationMs(of:)` in `Backyamon/Audio/Capture/AudioRecorder.swift`); `AssetUploader.live(socket:).uploadSample(...)` (create-asset → presigned PUT); `SampleUpload.swift` helpers (`SampleKind`, `sampleMetadataJSON`, `createAssetPayload`, `parseCreateAssetAck`, `makeUploadRequest`); `AssetModels.swift` (`Asset`, `SfxMetadata`, decoders, `SocketClient` asset RPCs); `AssetManager` equip store; `SampleTests` target.
- **Riddim dub engine (on `feat/dub-music-generator`, merged in by the prerequisite):** `InstrumentID` (defined in `RiddimPattern.swift`: `String, CaseIterable` — `kick, snare, hat, shaker, perc, bass, organ, skank, melodica`), `RiddimPattern`, `SampleLibrary`, `RiddimEngine`, `Chord`, `Resampling`, `Presets`, the bundled `Audio/Riddim/Samples/*.wav` kit, and `RiddimTests`.
- **Gallery / community:** SP3 reuses `AssetManager.findInGallery(id:socket:)` so a community-published riddim voice equips for free (IDs only persisted; payloads re-fetched).
- **Server contract:** unchanged. SP3 reuses `AssetType.sfx` with an extended slot vocabulary; **no new server type, no new RPC.** `decodeAsset` drops any unknown `type` (verified line 180 of `AssetModels.swift`), so a new `sample` type is deliberately avoided.

## Decisions

| # | Question | Decision | Why |
|---|----------|----------|-----|
| 1 | Per-voice override model | Add a runtime override API to `SampleLibrary`: `setOverride(buffer:rootMidiNote:for:)` / `clearOverride(for:)`; `buffer(for:)`/`rootMidiNote(for:)` prefer overrides. | The engine consumes voices only via those two getters. Overriding at the library layer makes the swap take effect everywhere with no engine-logic change. |
| 2 | Distinguishing a drum override (no repitch) from "no override" | Store overrides as `overrideBuffers: [InstrumentID: AVAudioPCMBuffer]` **plus** `overrideRoots: [InstrumentID: Int?]` (note the `Int?` value). Membership in `overrideRoots` means "overridden"; a `nil` value means "drum — do not repitch". | `rootNotes` is a `private let` constant with no entry for drums. A plain `[InstrumentID: Int]` cannot represent "overridden but rootless". `rootMidiNote(for:)` must check `overrideRoots.keys.contains(id)` first, return its (possibly-nil) value, else fall back to the constant. |
| 3 | Engine instance ownership | New `@MainActor` singleton `RiddimEngineHolder.shared` owns one `RiddimEngine` (lazy, throwing init handled) and exposes its `SampleLibrary`. Add `var sampleLibrary: SampleLibrary { library }` to `RiddimEngine`. | Nothing currently creates a `RiddimEngine` or can reach its private library. The holder gives `RiddimVoiceLoader`, `AssetManager`, and the Generate/Play UI a single object to mutate and render from. |
| 4 | New server `sample` type vs reuse sfx | Reuse `AssetType.sfx`; add `case riddimVoice(voice:rootMidiNote:)` to `SampleKind` with `assetType == .sfx`; carry `slot = "riddim-<voice.rawValue>"` and optional `root_midi_note` in the same metadata JSON. | `decodeAsset` silently drops unknown types; a `sample` type needs a server change. `SfxMetadata.slot` is the established sample-binding pattern. |
| 5 | Persistence | Extend `AssetManager.Prefs` with `var riddim: [String: String] = [:]` (`InstrumentID.rawValue` → assetId). Add `@Published equippedRiddimIds`. | `AssetManager` is the canonical equip store (IDs only, payloads re-fetched, gallery fallback). A `var` with a default keeps pre-SP3 blobs decodable. |
| 6 | Routing riddim slots away from the SFX path | In **all three** `.sfx` branches of `isEquipped`/`equipAsset`/`unequipAsset`, check `slot.hasPrefix("riddim-")` and divert **before** the `prefs.sfx` write/read; `loadEquippedAssets` gets a **dedicated** riddim loop, not the `gameSoundForSlot` loop. | A riddim asset is `type == .sfx`. Without interception it lands in `prefs.sfx` and is silently dropped by `guard let game = gameSoundForSlot(slot) else { continue }` (line 190) — equip would appear to succeed but do nothing. |
| 7 | Buffer build & conversion | Make `SampleLibrary.loadMono` `internal static` (currently `private static`). New `RiddimVoiceLoader` downloads + URL-caches the asset, converts via `loadMono`, then `library.setOverride(...)`. | Engine format is fixed mono 44.1k; `loadMono` already does the exact `AVAudioConverter` downmix the bundled kit uses. Caching mirrors the SP1/SP2 on-disk discipline. |
| 8 | Repitch root note | Seed from the slot default (`bass: 33`, `organ/skank/melodica: 57`); allow a ±semitone stepper in the assign UI; store as `root_midi_note`. Drums set `root_midi_note == nil` and are never repitched. | `repitch()` is naive linear interpolation and needs a reference. There is no pitch-detection infra (out of scope). Drums (the headline beatbox case) need no root. |
| 9 | Capture/upload | Reuse SP1 verbatim. Only new surface is the voice-binding model + `AssignVoiceView`. | SP1 helpers are pure, tested, and produce the exact create-then-PUT protocol. |
| 10 | Imported (non-`.m4a`) content type | For `fileImporter` imports, thread the real content type (derived from the file extension/UTType) through `uploadSample` instead of the hardcoded `AssetUploader.contentType = "audio/mp4"`. Cap sample length/size client-side in `AssignVoiceView`. | A WAV uploaded with `Content-Type: audio/mp4` mislabels the R2 object. `AssetUploader.contentType` is hardcoded; SP3 adds a per-call override. Recordings stay `audio/mp4`. |

## Architecture (files + responsibilities)

**Prerequisite (separate ticket, not SP3's diff)**
- `git merge feat/dub-music-generator → main` — routine merge; hand-resolve `project.yml` to one `Backyamon` scheme with `testTargets: [SampleTests, RiddimTests]` + `NSMicrophoneUsageDescription`; regenerate pbxproj/xcscheme via `xcodegen generate`.

**Modified**
- `Backyamon/Audio/Riddim/SampleLibrary.swift` — add `overrideBuffers: [InstrumentID: AVAudioPCMBuffer]` and `overrideRoots: [InstrumentID: Int?]`; `setOverride(buffer:rootMidiNote:for:)` and `clearOverride(for:)`; `buffer(for:)` returns the override when present; `rootMidiNote(for:)` returns the override (possibly `nil`) when the id is in `overrideRoots`, else the bundled constant. Change `loadMono` from `private static` to `internal static`.
- `Backyamon/Audio/Riddim/RiddimEngine.swift` — add `var sampleLibrary: SampleLibrary { library }` accessor. No other change.
- `Backyamon/Audio/AssetManager.swift` — `Prefs.riddim`; `@Published equippedRiddimIds`; riddim interception in `isEquipped`/`equipAsset`/`unequipAsset` (divert `slot.hasPrefix("riddim-")` before `prefs.sfx`); dedicated riddim loop in `loadEquippedAssets` that reads `SfxMetadata` (slot + `root_midi_note`) and calls `RiddimVoiceLoader`.
- `Backyamon/Online/SampleUpload.swift` — `case riddimVoice(voice: InstrumentID, rootMidiNote: Int?)` (`assetType == .sfx`); extend `sampleMetadataJSON` to emit `{slot: "riddim-<voice.rawValue>", duration_ms, file_size, root_midi_note?}` with `file_size` kept unconditional (identical to `.soundEffect`) and `root_midi_note` the only new optional key.
- `Backyamon/Models/AssetModels.swift` — add `let root_midi_note: Int?` to `SfxMetadata` (optional ⇒ backward-compatible); add `riddimVoice(forSlot:) -> InstrumentID?` mapping `"riddim-<raw>"` back to `InstrumentID(rawValue:)`.
- `Backyamon/Online/AssetUploader.swift` — let `uploadSample` accept an optional `contentType` override (default `Self.contentType`) so imports can pass their real type.
- `Backyamon/Views/MyStuffView.swift` — sheet entry "Use as instrument voice" → `AssignVoiceView`; for riddim-slot sfx assets, show the assigned `InstrumentID` + an EQUIP/UNEQUIP that routes through the riddim path.
- `project.yml` (post-merge already has both test targets) — no SP3-specific change required beyond what the merge produced; re-run `xcodegen generate` if any source files are added.

**New**
- `Backyamon/Audio/Riddim/RiddimEngineHolder.swift` — `@MainActor final class RiddimEngineHolder: ObservableObject`, `static let shared`. Lazily builds one `RiddimEngine` (handling the throwing init; on failure exposes `nil`/disabled state). Exposes `sampleLibrary`, an async `regenerateAndPlay()` that calls `engine.renderToFile()` then `SoundManager.shared.loadCustomMusic(fileURL:)` + `playCustomMusic()`, and `stop()`.
- `Backyamon/Audio/Riddim/RiddimVoiceLoader.swift` — `@MainActor` helper that downloads an asset URL (Caches/backyamon-audio URL-keyed cache, mirroring `SoundManager.cache`), converts via `SampleLibrary.loadMono`, then `library.setOverride(buffer:rootMidiNote:for:)`. `clearVoice(_:) → library.clearOverride`. **Awaits** load completion (not fire-and-forget). Errors swallowed (bundled default remains). Holds `RiddimEngineHolder.shared.sampleLibrary`.
- `Backyamon/Views/AssignVoiceView.swift` — Theme-styled like `CreateSampleView`: record (`AudioRecorder`) or `fileImporter(.audio)`; pick target `InstrumentID`; for pitched voices a root-MIDI stepper seeded from the slot default; client-side length/size cap. On Save: `AssetUploader.live(socket:).uploadSample(... kind: .riddimVoice(voice:rootMidiNote:), contentType:)` then `AssetManager.shared.equipAsset(assetId:socket:)`. Takes `(socket: SocketClient, onSaved: () -> Void)`. Use `.cancellationAction`.
- `Backyamon/Views/RiddimPlayView.swift` — minimal "Generate & Play" surface: a button that calls `RiddimEngineHolder.shared.regenerateAndPlay()` (pull-based render after overrides are applied) and a stop button. This is what makes the swapped voice **audible**.
- `SampleTests/RiddimVoiceTests.swift` — unit tests in the existing `SampleTests` target (reused, not new). See Testing.

## Data flow

1. **CAPTURE (reuse SP1):** record via `AudioRecorder` (AAC mono 44.1k → `sample-<uuid>.m4a`) or `fileImporter(.audio)` import; `audioDurationMs(of:)` computes duration; `AssignVoiceView` enforces a length/size cap.
2. **ASSIGN:** user picks target `InstrumentID`; for pitched voices a stepper seeds `root_midi_note` from the slot default (`bass: 33`, melodic: `57`); drums leave it `nil`.
3. **UPLOAD (reuse SP1):** `uploadSample(fileURL:title:kind:.riddimVoice(voice:rootMidiNote:),durationMs:,contentType:)` → create-asset `{type: sfx, title, metadata: {slot: "riddim-bass", duration_ms, file_size, root_midi_note}, needsUpload: true, contentType, fileSize}` → ack `{id, uploadUrl}` → PUT bytes to presigned R2.
4. **EQUIP/PERSIST:** `AssetManager.equipAsset(assetId:socket:)` detects `slot.hasPrefix("riddim-")`, writes `prefs.riddim["bass"] = assetId` (and **not** `prefs.sfx`), persists IDs only.
5. **RESOLVE+LOAD:** `loadEquippedAssets` refetches `listMyAssets`, indexes by id, falls back to `findInGallery`; the dedicated riddim loop reads `SfxMetadata` (slot + `root_midi_note`) and calls `RiddimVoiceLoader`.
6. **BUFFER OVERRIDE:** `RiddimVoiceLoader` downloads (URL cache), converts to mono 44.1k via `SampleLibrary.loadMono`, then `library.setOverride(buffer:rootMidiNote:for:.bass)` on `RiddimEngineHolder.shared.sampleLibrary`.
7. **RENDER + PLAY (pull-based, SP3-owned):** user taps Generate in `RiddimPlayView` → `RiddimEngineHolder.regenerateAndPlay()` → `engine.renderToFile()` (the now-overridden `library.buffer(for:.bass)`/`rootMidiNote(for:.bass)` feed `sampleForHit`) → `SoundManager.loadCustomMusic(fileURL:)` + `playCustomMusic()`. The user's kick/bass is now audible in the dub loop.
8. **UNEQUIP:** `AssetManager` clears `prefs.riddim[slot]` and calls `RiddimVoiceLoader.clearVoice → library.clearOverride(for:)`; the next Generate uses the bundled default.

## Error handling

- **Riddim engine init failure** (missing bundled WAV): `RiddimEngineHolder` catches the throwing `init`, exposes a disabled state; UI shows "Riddim unavailable" rather than crashing.
- **Download/convert failure** in `RiddimVoiceLoader`: swallowed; the bundled default voice remains; no override is set.
- **Async ordering:** `setOverride` is awaited inside `loadEquippedAssets` before any render. Render is **pull-based** (user taps Generate), so there is no race between an in-flight override load and a render — the override is already applied at startup/equip time.
- **Network failure** in `loadEquippedAssets`: existing behavior — leave state in place, return early.
- **Upload failure:** propagated from `uploadSample` to `AssignVoiceView`, surfaced as an error; the asset row may be orphaned (inherited SP1 gap, out of scope).
- **Imported odd formats:** `loadMono`'s `AVAudioConverter` handles most stereo/non-44.1k inputs; the client-side length/size cap bounds the `+64`-frame slack risk. Wrong/absent `root_midi_note` only affects pitched voices; drums are unaffected.

## Testing

Unit tests live in the existing **`SampleTests`** target (reused). To avoid depending on the 9 bundled WAVs resolving in the `SampleTests` host bundle, **engine-touching override tests construct an `AVAudioPCMBuffer` in memory** and call `SampleLibrary.setOverride`/`clearOverride`/`buffer(for:)`/`rootMidiNote(for:)` directly — no `Bundle.main` WAV load.

- `SampleLibrary.setOverride(buffer:rootMidiNote:for:.bass)` makes `buffer(for:.bass)` return the override and `rootMidiNote(for:.bass)` return the override root; `clearOverride(for:.bass)` restores the bundled default (verified via `buffer(for:)` non-nil after clear — requires a real `SampleLibrary()` only if you assert the *restored* value; the in-memory test asserts override-then-clear with a second `setOverride`).
- A **drum** override: `setOverride(buffer:rootMidiNote:nil,for:.kick)` ⇒ `rootMidiNote(for:.kick) == nil` (so `sampleForHit` won't repitch), distinct from "no override".
- `SampleKind.riddimVoice(voice:.bass, rootMidiNote:33).assetType == .sfx`; `sampleMetadataJSON` round-trips `slot == "riddim-bass"` and `root_midi_note == 33` through `decodeSfxMetadata()`.
- `riddimVoice(forSlot: "riddim-kick") == .kick`; unknown slot ⇒ `nil`.
- `AssetManager.Prefs` decodes a pre-SP3 (riddim-less) JSON blob without loss (`riddim == [:]`).
- Equipping a riddim-slot sfx asset populates `prefs.riddim` and **not** `prefs.sfx`, and riddim ids never appear in `equippedSFXIds`.
- Upload assertions use injectable closures, mirroring `AssetUploaderTests`.

Manual verification: record a beatboxed kick → assign to `.kick` → equip → open `RiddimPlayView` → Generate & Play → hear the loop with the user kick → unequip → Generate again → bundled kick returns.

## Out of scope

- A dedicated server `sample` `AssetType` and any server / `PROTOCOL.md` changes (reuse sfx + metadata extension).
- Automatic pitch/root-note detection from audio.
- Per-voice loudness normalization / auto-gain (slot gain inherited as-is).
- Time-stretch / high-quality pitch shifting (engine keeps naive `repitch`; long melodic samples stretch).
- Stereo or >44.1k engine support (downmix/resample only).
- A full pattern/progression/Presets editor and the broader in-game generate surface (the dub branch's Phase 2). SP3 ships only a **minimal** Generate & Play trigger to prove audibility.
- Publish-to-gallery UI for riddim samples (community samples remain consumable via `findInGallery`).
- Orphaned-upload cleanup and a get-asset-by-id RPC to replace full-gallery scans.
